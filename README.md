# 現場写真・電子黒板（試作）

地点・写真項目を選んで撮影／取り込み、電子黒板を合成するPWAです。写真を外部へアップロードする処理やAPI課金はありません。フレームワーク・外部CDN・実行時の外部パッケージに依存しません。

## PCで起動

Node.js 18以降（テスト用）とPython 3を使用します。依存パッケージのインストールは不要です。

```sh
cd /workspace/genba-shashin-kokuban
npm test
npm start
```

ポート8080で起動します。ローカルPCのlocalhostではPWA機能を確認できます。スマホからPCのLAN IPにHTTPで接続しても、PWAやカメラ等の機能は保証されません。

## スマホで試すための配布

公開先：<https://cota-coach.github.io/genba-shashin-kokuban/>。GitHub Pagesの `main` / root から配信しています。

GitHub Pagesを使う場合は、コードをGitHubへ反映した後、リポジトリの Settings → Pages → Deploy from a branch で main / root を指定します（利用可否は契約・リポジトリ公開範囲によります）。この設定はファイルをWebに公開するため、機密データはリポジトリに入れないでください。撮影写真は端末内に保存され、リポジトリには入りません。

- iPhone：SafariでHTTPSの配布先を開き、共有 → ホーム画面に追加。
- Android：ChromeでHTTPSの配布先を開き、メニュー → アプリをインストール／ホーム画面に追加。
- 初回は通信が必要です。地点・設定の「オフラインの準備状況」が準備済みになった後、機内モードで再起動して確認してください。
- 更新時は `sw.js` のキャッシュ名を変更してください。「新しい版に更新する」が表示されたら、未保存の写真を保存してから押してください。表示されない場合は一度開き、アプリと同じサイトのブラウザタブをすべて閉じてから再度開くと更新されます。アプリ更新のためにブラウザデータを削除しないでください。保存写真も消えます。

## 撮影から写真アプリへの保存

1. 「地点・設定」で実際の地点を登録。
2. 「撮影」で地点、工種、写真項目を選択。
3. 「黒板を見ながらカメラを起動」でカメラを許可し、全画面の撮影画面で「撮影」。矢印で黒板を少しずつ移動、中央ボタンで中央へ移動、＋／−で黒板を拡大縮小できます。黒板または「文字編集」をタップすると地点・工種・写真項目・日時・デザインを変更できます。高画質を優先する場合は「標準カメラで撮影」または「写真を選ぶ」。標準カメラを開くかどうかはブラウザ・端末に依存します。
4. 黒板のデザイン・位置・サイズ・日時を確認。
5. 「黒板を合成して端末内に保存」。書き込みが完了してから完了表示します。
6. 「保存写真」→「合成写真を共有」→ 端末の共有画面で「画像を保存」等を選択。

**写真アプリへの自動保存は保証できません。** 共有先に写真保存がない端末は「合成JPEGを保存」でファイルに保存し、OS側で写真アプリに取り込んでください。ダウンロードは通常「ファイル／ダウンロード」に入ります。カメラから取り込んだ原本も、写真アプリへ自動保存されるとは限りません。

PCでファイル名を使って仕分けるためには、**写真アプリ経由で名前が変わる転送を避け、「一式を共有」でファイルへ保存、または原本・合成JPEG・管理JSONを個別にダウンロード**してください。保存先で元のファイル名が保持されていることを確認します。

## まとめてPCへ渡す（v0.4.0）

「保存写真」は **撮影・取込操作日 → 地点名** ごとに表示します。各地点の「この地点をZIPにまとめる」、日付の「この日すべてをZIPにまとめる」を選ぶと、端末内だけでZIPを作成します。準備完了後に「ZIPを保存」または「ZIPを共有」を押してください。共有先がZIPを扱えない場合は保存を使用します。元の保存写真は削除しません。

「ZIPに入れるもの」で黒板付き写真・原本・管理JSONを個別に選べます。JSONを外すと「書き出し一覧.json」も入りません。黒板付き写真だけならJPEGのみのZIPになります。選択内容は次回にも保持し、全部オフでは書き出せません。

```text
20261027/
  白上川1K4R_地点名の識別用ID/
    …__board.jpg           ← Excel用の黒板付き写真
    原本/…__original.jpg   ← 黒板なし画像
    管理情報/….json        ← 地点・工種・日時など
書き出し一覧.json           ← 件数とファイルの対応表
```

地点名は保存時の名前でグループ化します。名前が違うものは別グループです。同じ表記に変換される名前が重ならないよう、フォルダには識別用の短いIDが付きます。黒板で手動変更した日付ではなく、撮影・取り込み操作日でまとめます。過去の保存写真も対応します。

JPEGの画像部分は再圧縮せず、管理情報だけを追加してZIPへ格納します。写真はすでに圧縮されているためZIPで容量が大幅に減るわけではありません。スマホのメモリ消費を抑えるため、1回のZIPは250MB以下に制限しています。超える場合は地点単位に分けてください。保存完了や共有画面の終了だけではPCへの転送完了を判定できないので、書き出し済み扱いで自動削除することはありません。

### iPhone → Windowsの例

会社のルールでクラウド保存が認められ、iCloud Driveに空き容量があれば、次の方法が手軽です。

1. アプリでその日のZIPを作り、「ZIPを保存」。iPhoneの「ファイル」で保存先を確認する（ダウンロード先は端末設定に依存します）。
2. 保存先が「このiPhone内」なら、ZIPをiCloud Drive内の任意のフォルダへコピー／移動。共有から「ファイルに保存」を選べる場合は、直接iCloud Driveへ保存しても構いません。
3. Windowsで同じApple AccountのiCloud Driveを開く。Windows用iCloudがなくても、ブラウザのiCloud.comからダウンロードできます。
4. WindowsへZIPをダウンロードし、右クリック →「すべて展開」。写真の枚数、画像、管理情報を確認します。

iPhoneの写真同期ではなく、ZIPファイルを渡します。USBケーブルで接続しただけでは、iPhoneの「ファイル」内のZIPをWindowsから直接見られるとは限りません。クラウドを使わない場合は、端末に対応するUSBメモリへ「ファイル」からZIPを保存してWindowsへ渡す方法があります。機器の対応端子・アダプタは端末ごとに確認します。

「保存写真」→「仕分け用データを確認」で地点・工種・項目・日時を確認できます。「JPEG内のデータを確認」は、実際に書き出すJPEGから埋め込み情報を読み出します。「管理JSONを保存」は同じ管理情報を別ファイルで保存する選択肢です。v0.5.0以降は黒板付きJPEGだけでもAIなしで読み取れます。

ライブ撮影はブラウザへ届いた動画の1フレームをJPEG化します。標準カメラの静止画と同じ画質・解像度は保証しません。要求値ではなく実際の映像寸法を画面へ表示し、その寸法で保存します。黒板プレビューと撮影画像をトリミングせず同じ比率で扱います。端末の向きが変わった場合も位置を実機確認してください。撮影後・別画面へ移動・アプリが非表示になった時はカメラを停止します。

全画面の撮影画面では背景ページのスクロールをロックします。縦横の持ち替えでも、移動・サイズ・撮影ボタンを画面内に配置します。ブラウザのアドレスバーを必ず隠せるわけではありません。ホーム画面から起動するとブラウザのバーを避けて使えます。映像は切り抜かないため、画面とカメラの縦横比が違う場合は黒い余白が出ます。黒板の位置・サイズは次回起動にも保持し、保存JPEGとJSONへ同じ設定を反映します。四隅へ戻す操作は「文字編集」内から行えます。

撮影画面で地点名を編集すると地点一覧の登録名も更新します。保存済み写真の名前・管理情報は変えません。編集のキャンセルは元のままです。文字の入力中だけ編集パネル内をスクロールできます。

## 写真と管理情報

- 原本：取り込み方式はブラウザが受け取った画像ファイルのバイト列を保持。元のEXIFは加工しません。ただし、カメラ／OSがブラウザへ渡す前の変換は制御できません。ライブ撮影方式の「原本」は黒板なし動画フレームのJPEGで、センサー原本やEXIF付き静止画ではありません。
- 合成写真：読み込んだ画像と同じピクセル寸法のJPEG（品質指定0.95）。元写真のEXIFをそのままコピーせず、本アプリが記録した管理情報を新しいEXIFとして埋め込みます。
- 管理JSON：地点、工種、項目、端末ID、写真ID、取込日時、黒板表示日時、原本／合成写真のファイル名等。
- 試作の画像上限は2500万画素です。超過時は原本を勝手に縮小せずエラーを表示します。
- 日付の自動値は撮影・取り込み操作時の端末時計です。ライブ撮影ではシャッター操作の日時を `capturedAt` に記録します。標準カメラ／写真選択ではEXIF撮影日時を読み取らず `capturedAt` は未取得のままです。過去写真の表示日時は黒板編集で修正します。
- 削除は明示的な確認操作のみ。元の写真アプリや取り込み元ファイルは削除しません。

詳しくは [データ仕様](docs/data-format.md) と [実機検証](docs/device-checklist.md) を参照。

## 自動検証

`npm test` で命名・日時・黒板位置を検証します。PlaywrightとChromiumがある検証環境では、サーバー起動後 `node tests/browser.cjs` で登録、画像合成、原本のバイト一致、再起動、ダウンロード、オフライン保存、書き込み失敗後の再試行、管理情報表示・JSON出力、模擬カメラによるライブ撮影・停止・権限拒否を検証できます。320×568、390×844、667×375、844×390の4サイズで、ボタンの収まり・スクロールロック（ホイールとタッチ操作）・黒板の移動／拡縮／編集／キャンセル・位置の保存と画像への反映も検証します。これはPC上のChromiumによるモバイル模擬テストであり、スマホの実カメラや写真アプリへの保存を検証したものではありません。

## 現時点の範囲

ライブ撮影／標準カメラ取り込み、撮影中の黒板位置表示、黒板合成、地点編集、工種・写真項目編集、緑／白の黒板、四隅・サイズ変更、日時切替、IndexedDB保存、仕分けデータ表示、個別共有・ダウンロード、オフライン用キャッシュを実装しています。

Python仕分け、Excel連携、EXIF日時取得は未実装です。日付／地点ごとのZIP書き出しは実装済みです。提出先の電子小黒板規定への適合認証もありません。実業務へ投入する前に、実機検証と提出先ルールを確認してください。

## JPEG自体に管理情報を記録（v0.5.0）

- 地点名・工種・写真項目・取込日時・黒板表示日時などをJPEGのEXIFへ記録します。写真ファイル単体でもPythonで読み出せます。
- Windows向けのタイトル（地点名）、件名（工種・項目）、コメント、キーワードも記録します。Windowsではファイルを右クリック → プロパティ → 詳細で確認できます。表示される項目は使用ソフトに依存します。
- ライブ撮影は取得済みの撮影日時を標準EXIFのDateTimeOriginalへ記録し、時差も記録します。標準カメラ・既存写真の取込では元のEXIF撮影日時を読み取っていないため、撮影日時を捏造せず取込日時と別管理します。黒板の日時を手動編集しても実際の撮影日時は変えません。
- 設定のGPS記録は初期状態でオフです。オンにしたライブ撮影でのみ、ブラウザの位置情報（GPS・Wi-Fi等）を要求し、取得できれば緯度・経度・精度・取得時刻を保存します。GPSを含むJPEGやJSONを共有すると座標も渡ります。拒否・時間切れの場合も画像はGPSなしで保存できます。既存画像へ現在地を後付けしません。
- 以前の保存写真は、最新版から書き出すコピーへ管理情報を追加します。保存済みJPEG・原本は上書きしません。以前に外へ書き出したJPEGは再度書き出してください。
- メタデータは画像編集・再保存・SNS・共有アプリ等により削除される場合があります。PCへはZIPまたはファイルのまま渡し、受け取ったJPEGで確認してください。埋め込みは改ざん防止署名ではありません。

PCでJPEGだけから確認する例（Python 3標準ライブラリのみ、追加パッケージ不要）：

```sh
python tools/read_photo_metadata.py photo.jpg
python tools/read_photo_metadata.py photo.jpg --json
```

`--json` はJPEG内から読み取った全情報を画面へ表示します。別のJSONファイルを用意する必要はありません。将来のPython仕分けではこの読み取り関数を使えます。自動テストは7種類のZIP選択、画像のみZIPからの情報復元、GPS成功・拒否、JPEGの画像部分と原本の保持を確認します。Pillowがあるテスト環境では独立したEXIFパーサーによる互換性検証も行います（アプリの実行には不要）。
